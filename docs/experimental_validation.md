# Experimental validation plan

Use this plan after the target build, electrical review and supervised integration checks pass. Each result needs a dated raw file, observer notes and the exact model and firmware versions. Keep source files under inputs unchanged. Store new recordings in an approved external experiment location. Synthetic vectors are software references, with separate provenance from every lab recording.

## Before each session

1. Give each run a unique ID. Record firmware commit, board and sensor IDs, active model IDs, boot identity, clock source, room dimensions, measurement location, ventilation, fan mode, door/window state, reference instrument details and operator. Synchronize and document clock offset and drift with the reference logger. Preserve device uptime and sequence independently. Capture wall-clock labels with an explicit timezone.
2. Inspect the device, scope the Sharp timing and verify live data through the acceptance endpoint. Record the warm-up, readiness, error and freshness states rather than trimming them from the raw data.
3. Keep an independent event log for people entering/leaving, operator actions, fan changes, airflow disturbances, network outages and calibration start/end. Mark missing and invalid observations. If the body of evidence is incomplete, identify the affected interval and avoid treating held values as new measurements.
4. Plan independent sessions across days and hold out entire runs or rooms where applicable. Use exploratory results to propose acceptance criteria before a separate validation run. Document any deviations.

## Collection and analysis

| Experiment | Procedure | Required evidence and analysis |
|---|---|---|
| Empty-room reference | Independently confirm the room is empty. Keep airflow steady and record doors, windows and fan state. Observe the initial equilibration, then run owner-confirmed calibration when eligible. Repeat on separate days under documented conditions. | Export telemetry and the calibration CSV. Log reference CO₂, T/RH, room volume, occupancy event and baseline start/end. Report median, range, scaled MAD, missing counts and version comparison, with actual room confirmation. |
| Ascending occupancy | Start from a measured empty baseline. Use participant groups approved by the lab and an independent observer. Record actual entry/exit events, stable periods, transitions and ventilation changes. Include separate descending or repeat sessions to expose lag and confounding. | Record ground truth in an independent CSV with timestamp, session, stage, actual people and event. Preserve SCD observations and the model estimates with readiness/domain flags via the authorized backend/owner data views. Align by capture timestamps. Compare on held-out sessions and report absolute and signed count error plus coverage. Keep the unverified 924-row dataset out of measured evaluation. |
| MQ135 normal response and challenge | Record clean-air sessions spanning allowable T/RH after firmware warm-up. For challenges use the laboratory's approved non-hazardous protocol and documented reference conditions. Keep exposure designation independent of the VIGIL result and observe return to baseline. | Capture paired SCD time, T/RH, MQ seq, ADC, GPIO/AO voltage, positive Rs, validity, anchor version, residual/score/votes where retained and detector state. Keep a separate challenge-event CSV with start/end, condition and independent reference. Evaluate excursions, false alerts, missed events, latency and repeatability. Analysis concerns the gas-response sensor only. |
| Sharp dust response | Collect a stable baseline with verified LED/pulse timing. Repeat under the lab's approved optical reference/response protocol without altering the acquisition circuit. Mark times with fan/airflow changes or timing rejection. | Preserve every ON/OFF/delta aggregate, pulse min/max, rejected/missed counts and validity. Record independent reference readings and intervention notes. Compare rolling median, scaled MAD, threshold bands and persistent flag with the approved baseline. Report repeatability and limitations of the relative response. |
| CO₂ forecast | Run long enough to populate forecasting across independent fresh CO₂ samples and observe the ten-minute targets. Include stable, rising and falling periods. Keep outage gaps and missed targets explicit. | Save the session telemetry with three forecast outputs, an origin/target/actual review CSV and the observed matches count. Use exactly the backend rule for determining matched targets. Report target coverage, MAE, RMSE and signed prediction-minus-actual bias on common pairs, plus the count. When exact-match pairs are absent, report unavailable errors. |
| Ventilation | Begin with a safe indicator and supervised test conditions. Observe Auto trigger and recovery on a controlled run. Record manual requests, stale data and local override evidence with independent GPIO/actuator measurement. | Combine telemetry fan state/reason and override flags with a command/event CSV showing timestamp, request, intended mode, GPIO/actuator observation and conditions. Compare measured transitions with the approved threshold, latch, recovery and expiry timing. Review false starts and delays. |
| Calibration repeatability | Repeat independently prepared baseline sessions for each sensor. Compare across operators or days when practicable. Keep both failed and successful attempts and perform a supervised restore. | Export raw session CSVs, gate evidence, pass/fail reasons, version IDs, source, parameters and boot/session IDs. Compare the distributions, failure rates, changed parameters, warm-up duration and version restore. A passed gate is evidence about that run's eligibility. |

### File manifest for each run

- `manifest.csv` records run ID, local/UTC time, firmware commit, boot IDs, model IDs, reference instruments, conditions and evidence filenames.
- `telemetry-<boot>.csv` is the original owner export. Keep blank fields and full sample order.
- `calibration-<session>.csv` is the owner export with legacy column order for that sensor, including blanks where the firmware does not provide the original logger field. Estimated UTC fields are distinct from native captured uptime.
- `events.csv` and `reference.csv` are observer records aligned to the independent time reference. Include separate labelled occupancy, challenge and fan events as relevant.
- Derived analysis tables retain the original file names and filtering decisions. If a desired diagnostic is unavailable in an export, document its provenance from an authorized retained result or record it separately during the run. Avoid filling missing measurements through inference.
