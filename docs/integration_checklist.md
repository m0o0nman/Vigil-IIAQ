# Ordered integration checklist

Use an isolated, authorized Firebase/Vercel project, the exact release commit and a supervised assembly. Start with a safe fan indicator or otherwise unloaded driver before connecting the installed fan. Record board, core and library versions, commit, project ID, region, boot ID, UTC time and operator. Keep credentials out of screenshots and logs.

**Status** records the software evidence available at Phase 6. Enter an actual physical pass/fail and evidence reference in the empty last column. Sample measurements and dashboard states used for software verification are synthetic.

| # | Check and preparation | Procedure | Expected behavior and acceptance criterion | Phase 6 status | Physical result / evidence |
|---|---|---|---|---|---|
| 1 | Target compile. Install the pinned core and libraries. | Verify the unconfigured and network-configured sketches in Arduino IDE. | Both builds complete for NodeMCU-32S. Record memory sizes and warnings. | CLI blocked before compile. | |
| 2 | Initial acquisition. Check wiring and safe rails with the load isolated. | Flash, reset and sample CO₂, T/RH, MQ ADC/voltage/Rs and Sharp ON/OFF. | Values, ages and valid flags follow each sensor's validity rules. No permanent AP or unexpected fan output at boot. | ADC source parity and host gates passed. | |
| 3 | Sharp timing. Connect a suitable scope to the control signal. | Measure under steady capture, upload and reconnect. Record bounds and rejected/missed counts. | 10,000 µs nominal period, 280 µs sample, 320 µs pulse. Accepted pulse width 300–340 µs and sample offset 280–300 µs. Aggregate counters agree. | Timing expressions and boundaries passed on host. | |
| 4 | Wi-Fi provisioning. Use an authorized AP and a device without valid saved settings. | Open the temporary portal, submit settings, confirm station joins, then reboot. | Portal disappears after join, and saved credentials work on reboot. | Code present. Radio and portal unverified. | |
| 5 | HTTPS ingest. Configure URL, trustworthy CA, SNTP and device secret. | Observe a successful POST/ACK. In the isolated setup, test a wrong device secret and unsuitable trust configuration. | Valid traffic returns HTTP 200 and exact ACK. Invalid secret receives 401. Invalid trust prevents accepted uploads. | Backend auth and C++ reply parser passed separately. | |
| 6 | Firebase updates. Publish approved rules and indexes in the acceptance project. | Sign in as owner and observe first accepted device batch. | 7 | Live dashboard. Open owner Monitor on a current boot. | Match CO₂, climate, timestamp and actual fan state to the current projection. | Live labels follow the documented UI bands and unavailable states. No forecast is presented as an observation. | Chromium fixtures passed. | |
| 8 | Occupancy. Use an independently labelled occupied session and usable window. | Record the model output including warm-up and range context. Compare to the ground-truth event log after export. | Counts are approximate and in-range estimates use even rounding. Record real errors without inventing an accuracy target. | Synthetic golden parity passed. | |
| 9 | MQ135. Begin after warm-up and with a usable reference. | In an approved lab experiment compare baseline and designated challenge intervals. | Valid samples preserve raw data and detector status. Alerts, if any, obey the approved score and vote gates. Capture false and missed detections. | Synthetic MQ vectors passed. | |
| 10 | Sharp response. Use the lab's approved optical reference protocol. | Record a stable window and an approved response change with pulse diagnostics. | Filtering consumes all valid aggregates in order and resets on invalid data. Record response changes and any persistent-high evidence. | Synthetic Sharp vectors passed. | |
| 11 | Calibration. Confirm empty room, quiet airflow and no fan operation. | Run a stable eligible session. Run an unsuitable or aborted session separately. | A passing run activates a traceable successor. Failed or aborted runs retain the predecessor and expose reasons and CSV evidence. | Synthetic transaction and browser tests passed. | |
| 12 | Forecasting. Allow sufficient independent fresh observations. | Compare forecast origins and exact target timestamps to observations. | Forecast methods are separate, matched counts are correct, and errors remain unavailable when no valid pair exists. | Golden and legacy ramp fixtures passed. | |
| 13 | Auto. Begin with a supervised indicator and a usable SCD reading. | Observe the approved CO₂ rise and release rules in a controlled run. | Auto starts on original immediate or preventive criteria. Minimum run and sustained recovery follow the firmware policy. | Server and host policy paths tested. | |
| 14 | Manual controls. Use a fresh, unlatched device under supervision. | Request Freshen now, Off, then Auto. Compare requested mode to actual GPIO state. | The short lease expires. Actual fan state agrees with device measurements. UI treats Off as a request until telemetry arrives. | Browser and host lease checks passed. | |
| 15 | Local safety. Use an indicator and an approved test setup for high and stale CO₂. | Request Off during a high-CO₂ local latch. Remove fresh CO₂ during an ON authorization. | High fresh CO₂ retains local authority. Stale/invalid CO₂ forces OFF despite an ON request. Capture documented minimum and recovery timing. | C++ safety tests passed. | |
| 16 | Network outage. Start from a verified live pairing. | Disconnect station connectivity and restore it before and after the queue capacity is reached in separate trials. | Capture continues, live marks offline, leases expire, reconnect resumes. | Reconnect behavior simulated on host. | |
| 17 | Replay. Record sequences during both outage trials. | Compare replay with pre-outage and post-reconnect history, including retries. | Unique history rows, preserved capture order, explicit overflow gaps. Replay cannot issue a current fan lease. | Host FIFO and mocked backend passed. | |
| 18 | Device reboot. Record the current boot and queue state. | Reboot during an isolated trial and observe session transition. | New boot ID, reset sequence, independent history. Unsent RAM may be lost. Old replay leaves current live state intact. | Mocked boot boundaries passed. | |
| 19 | Stale and invalid readings. Arrange safe sensor disconnection in the lab. | Invalidate SCD or Sharp input, observe age and restore valid capture. | Invalid data suppresses current labels and triggers the appropriate reset. The last valid observation timestamp remains distinguishable. | Host validity and browser stale checks passed. | |
| 20 | CSV export. Collect recorded telemetry and a calibration session. | Download both as the owner. Check headers, sequence order and availability fields. | Telemetry includes the open minute and calibration CSV uses source column order. Missing values stay blank. Nonowner is denied. | Mock CSV checks passed. Live transfer unverified. | |
| 21 | Model rollback. Record an active successor and its predecessor. | Restore the previous calibration with owner confirmation and observe the next capture. | Active pointer changes once, prior documents remain and rolling state rebuilds. A retry never activates an extra version. | Mocked activation/restore and state reset passed. | |
